# Bluesuite — Premium Web3 Product Suite

Build a production-quality website and application shell for **Bluesuite**, a premium blockchain tooling platform created by **BLUEVALLEY LABS**.

**BLUEVALLEY LABS:** https://x.com/bluevalleylabs
**Founder:** theweb3proxy
**Motto:** "building tools for the blockchain"

Bluesuite should feel like a serious, highly engineered Web3 software company rather than a generic crypto landing page. The design must be distinctive, polished, fast, minimal, and premium.

Do not produce an AI-looking website. Avoid generic gradients, glowing blobs, excessive glassmorphism, floating 3D objects, robot imagery, AI-generated illustrations, stock imagery, or cliché Web3 visuals.

Use strong typography, sophisticated spacing, subtle borders, excellent hierarchy, restrained motion, premium micro-interactions, and carefully designed UI components.

---

## 1. BRAND DIRECTION

Use the attached BlueValleyDAO image as the primary reference for the brand palette and visual identity.

Extract inspiration from its dominant colors:

* Electric Blue: approximately `#000CFF`
* Cyan / Aqua: approximately `#93FDF9`
* Deep Blue: approximately `#030B80`
* Bright Azure: approximately `#038AE4`
* Near-black: `#05070D`
* Soft white: `#F7FAFC`

The site should be **dark-mode first**, with a fully designed light mode.

### Dark mode

Dark mode should be the primary experience.

Use:

* Near-black backgrounds
* Very deep navy surfaces
* Electric blue as the primary accent
* Cyan/aqua as a secondary accent
* White/off-white typography
* Subtle blue borders
* Extremely restrained gradients

Do not make the entire site blue. Blue should function as an accent and brand signal against sophisticated dark surfaces.

### Light mode

Light mode should feel equally intentional rather than simply inverting the dark theme.

Use:

* Warm/off-white backgrounds
* White cards
* Deep navy/black typography
* Electric blue accents
* Aqua used sparingly
* Very subtle blue-gray borders

Persist the user's theme selection.

2. Inspect the available project assets and images.
3. Inspect any existing frontend/backend architecture.
4. Inspect the Mojihood repository/infrastructure relevant to the snapshot functionality.
5. Identify the existing framework, package manager, routing system, styling system, and data layer.
